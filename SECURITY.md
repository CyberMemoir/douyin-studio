# Local execution and data boundaries

- The server listens only on `127.0.0.1`.
- Host and Origin checks reject non-local or cross-site requests; mutation requests also require a custom header. There is no public authentication or multi-user mode. Do not reverse-proxy the service onto the internet.
- Browser CDP attachments are restricted to local HTTP origins. CDP grants browser control: connect only to your own dedicated automation profile.
- Login Cookie values never appear in UI/API output. Runtime data is kept under `.data/`, ignored by Git. The application does not read your normal Chrome profile.
- Download requests accept discovered video IDs, not arbitrary URLs. Backend media addresses and every redirect must match an HTTPS platform-domain allowlist.
- Filenames are generated by the server. Download/file endpoints only serve indexed, completed, non-symlink MP4 files inside the configured download directory.
- Downloads validate the MP4 signature and transfer length, use temporary files and bounded size/time, and clean up on cancellation/failure.
- Do not commit `.env`, browser profiles, state snapshots, cookies, signed media URL caches or downloaded material. Keep custom data directories out of Git too.

To report a vulnerability, contact repository maintainers through GitHub's private vulnerability-reporting channel when enabled; otherwise open an issue with a minimal non-sensitive description and request a private contact path. Never attach live credentials or browser profiles.
